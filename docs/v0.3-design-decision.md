# v0.3.0 design decision: admission before dispatch, repair by re-quote

**Status:** Accepted for the v0.3.0 external-review candidate.

## Decision

`ReferenceProvider.commit()` returns a discriminated `CommitResponse`.
Known cross-unit admission failures are returned as `ADMISSION_REFUSED`,
before any commercial mutation is dispatched. Once admission passes, the
existing per-unit `CommitResult` is returned as `COMMIT_RESULT`; its
`APPLIED` / `REFUSED` / `INDETERMINATE` and reconciliation semantics are
unchanged.

A quote declares directional `REQUIRES_COINCLUSION` relations. The core
defines only their direction and binding scope. The binding owns operation
and state semantics and evaluates the quoted transitions against current
state through a small admission hook immediately before dispatch.

Each quoted unit carries two identities with different lifetimes:

- `unitRef` is quote-local and continues to correlate quote, commit result,
  and receipt.
- `unitLocator` is binding-scoped and can identify the same domain unit in a
  failure witness and a later quote. It is not globally meaningful.

The quoted unit also carries its opaque, binding-defined `transition`. This
lets the provider retain the exact submitted transition set without teaching
the core how to parse domain operations.

An admission refusal correlates to both `quoteId` and the originating
`proposalId`. Each failed relation carries an explicit witness disposition:
`COMPLETE`, `PARTIAL`, `UNAVAILABLE`, or `NOT_REPAIRABLE`. Only `COMPLETE`
claims that its non-empty `requiredTransitions` list is sufficient to repair
that one relation at the evaluated state. It does not claim that the whole
request will become admissible.

## Repair lifecycle

A caller may use a complete witness to construct a new `MutationProposal`
whose opaque `change` includes the original and required transitions. The
provider authorizes and quotes that new proposal normally. The resulting
quote has a new `quoteId` and may have new quote-local `unitRef` values; the
binding maps units across quotes with `unitLocator`.

The original quote is never amended, and `CommitRequest` does not accept an
unquoted transition. The new quote is independently subject to expiry,
snapshot, acceptance-constraint, authorization, idempotency, and fresh
admission checks. A complete witness can remove a discovery read, but it
does not create a no-requote path.

## Concurrency and failure boundary

The reference provider's observational admission hook is synchronous and runs
immediately before its in-process dispatch loop, with no asynchronous yield
between the two. The hook must not itself dispatch the commercial mutation.
This demonstrates evaluation-before-dispatch and a measurable no-dispatch
refusal. It is not a distributed lock or transaction guarantee. Bindings
backed by external state must document and implement their own atomic
validation/dispatch or final revalidation boundary. `evaluatedAt` and the
optional opaque `stateRef` are correlation evidence, not locks.

If dispatch may already have occurred, the provider must not return
`ADMISSION_REFUSED`; it must preserve per-unit commit determinacy and use
`INDETERMINATE` plus reconciliation where the outcome is unknown.

## Compatibility

This is v0.3.0 rather than a v0.2.x patch because requiring quoted
transitions/locators and changing `commit()` from `CommitResult` to the
`CommitResponse` union are breaking wire and TypeScript/API changes. Existing
providers must populate the new quote fields and explicitly implement or
fail closed on declared admission relations. No release tag is created by
this work.
