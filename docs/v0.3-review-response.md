# v0.3.0 review response: stable relations and live admission witnesses

**Status:** Experimental / External Review Candidate. This document records
MSE design changes informed by comments from Weston (`westonale`) in UCP
Discussion #799. The reported provider behavior is evidence; the MSE contract
proposed here is our response. It is not an accepted UCP requirement, an
implementation claim about Weston's system, or evidence of UCP adoption or
endorsement.

## What changed

- `CommittingUnit` now requires an opaque `transition` and a binding-scoped
  `unitLocator`. `unitRef` remains quote-local for quote/result/receipt
  correlation; it is not reused as a global repair identity.
- `MutationQuote.admissionRelations` is required (and may be empty). The only
  core relation type is the directional `REQUIRES_COINCLUSION`; operation and
  state vocabulary stay in the binding.
- `CommitResponse` is a discriminated outer response. `ADMISSION_REFUSED`
  reports a known pre-dispatch failure. `COMMIT_RESULT` contains the existing
  complete per-unit result.
- Each failed relation carries an explicit `AdmissionWitness`. Only
  `COMPLETE` with a non-empty, unambiguous, in-scope transition list claims
  local repair for that relation. It never claims whole-request admissibility.
- `ReferenceProvider` retains the originating proposal and invokes a
  synchronous binding evaluator immediately before its dispatch loop. A
  declared relation without an evaluator fails closed with `UNAVAILABLE`.
- The schema and TypeScript mirror now enforce the already-normative
  `APPLIED`-requires-`committedEffects` rule and exclude fields belonging to
  other per-unit outcomes; the consistency audit found the v0.2.0 artifacts
  had expressed this only in prose.
- `assertAdmissionRefusalWellFormed` rejects false correlation, undeclared or
  repeated relations, missing/empty witnesses, wrong-scope or repeated unit
  locators, quote-present units described as missing, and contradictory
  requirements for one locator. It deliberately does not claim to prove
  domain-level completeness from opaque transitions and state.

## Worked retail evidence

[`/examples/retail/admission-policy.ts`](../examples/retail/admission-policy.ts)
models the two reported gates against mutable order state:

1. Cancelling delivery requires cancellation of every goods unit that is not
   already cancelled and is not already cancelled by the submitted proposal.
2. Redeeming a goods unit requires delivery redemption only while delivery is
   `COMMITTED`.

[`admission-refusal.fixture.json`](../examples/retail/admission-refusal.fixture.json)
shows two missing goods cancellations. The correction is a new proposal
([`amended-proposal.fixture.json`](../examples/retail/amended-proposal.fixture.json))
and a new quote
([`amended-quote.fixture.json`](../examples/retail/amended-quote.fixture.json)).
No unit is appended to the original quote or commit request.

Behavioral tests exercise exclusions for already-cancelled and already-
requested goods, the committed-state redemption condition, no-dispatch
evidence, partial/unavailable/malformed witnesses, duplicate/wrong-scope/
unresolvable references, contradictory transitions, authorization at the
binding boundary, fresh-state evaluation, expiry, snapshot mismatch,
acceptance constraints, later refusal, and later `INDETERMINATE` plus
reconciliation.

## What this does not solve

- Co-inclusion is an admission rule, not an atomic transaction. A required
  companion can still be refused or indeterminate after admission. A binding
  that must prevent such an economic outcome needs a stronger execution
  guarantee.
- A complete witness removes a discovery read only for one relation at one
  evaluated state. It does not remove the new-quote step, grant authority,
  extend expiry, preserve a stale snapshot, satisfy acceptance constraints,
  or define idempotency behavior for changed content.
- The reference provider's synchronous in-process check is not proof of a
  distributed lock. External-state bindings must document their atomic
  validation/dispatch or final-revalidation boundary.
- A separate delivery unit plus admission dependencies does not represent a
  genuinely shared tax/effect whose causal ownership spans several units.
- The shrinking-missing-set property is demonstrated only for these reported
  retail gates. MSE does not claim it for every binding.

## Compatibility posture

v0.3.0 is a breaking minor revision in this pre-1.0 project, not a patch.
Required quote fields, the `CommitResponse` return union, and the tightened
discriminated `UnitResult` mirror break old closed wire-schema consumers,
TypeScript callers, and providers. §9 of the normative spec gives the
migration table. No release tag is created by this iteration.
